# MUT Shuttle Bus — React + Node.js + Oracle

เปิดและแก้ไขด้วย **Visual Studio Code (ไอคอนสีฟ้า)**

## เปิดโปรเจกต์

1. ถ้าได้รับ ZIP ให้แตกไฟล์ก่อน
2. เปิด VS Code → **File → Open Workspace from File…**
3. เลือก `Shuttle Bus.code-workspace` ในโฟลเดอร์โปรเจกต์
4. โค้ดหน้าเว็บอยู่ใน `client` และโค้ด Server อยู่ใน `server`

หรือใช้ **File → Open Folder…** เลือกโฟลเดอร์ที่มี `client`, `server` และไฟล์นี้

## รันบนเครื่องนี้

ติดตั้ง dependencies และตั้งค่า Oracle ใน `server/.env` บนเครื่องเจ้าของงานไว้แล้ว

เปิด **Terminal → New Terminal** สองช่อง โดยเริ่มที่โฟลเดอร์โปรเจกต์:

Terminal 1 — Server:

```powershell
npm.cmd run server
```

Terminal 2 — Client:

```powershell
npm.cmd run client
```

เปิด **http://localhost:5173** และเปิด Terminal ทั้งสองช่องทิ้งไว้ระหว่างใช้งาน

- กด `Ctrl+C` ใน Terminal แต่ละช่องเพื่อหยุด
- หลังแก้โค้ดและกด Save หน้าเว็บจะอัปเดต ส่วน Server จะเริ่มใหม่อัตโนมัติ
- เมื่อ Server เริ่มใหม่ให้ล็อกอินอีกครั้ง เพราะ session เก็บในหน่วยความจำ
- ถ้าพอร์ตถูกใช้อยู่ ให้หยุด Server/Client ชุดเก่าก่อนรันชุดใหม่
- มี `start-server.cmd` และ `start-client.cmd` สำหรับเปิดแยกกันด้วยการดับเบิลคลิก

ทางลัดใน VS Code: **Terminal → Run Task… → Shuttle: Run Server + Client** จะรันทั้งสองส่วนใน Terminal แยกกัน

## ส่งให้เพื่อน / ติดตั้งบนเครื่องอื่น

ส่ง ZIP ในโฟลเดอร์ `deliverables` ให้เพื่อนได้ ZIP มีโค้ดและคู่มือ แต่ไม่มีรหัสฐานข้อมูล, บัญชีเริ่มต้น, `node_modules` หรือข้อมูลส่วนตัวใน `.env`

1. ติดตั้ง Node.js รุ่น 22.12 ขึ้นไป (เครื่องเจ้าของงานใช้ 24.21)
2. แตก ZIP และเปิด workspace ตามขั้นตอนด้านบน
3. ติดตั้ง dependencies ใน Terminal ที่โฟลเดอร์โปรเจกต์:

```powershell
npm.cmd --prefix server ci
npm.cmd --prefix client ci
```

4. สร้างไฟล์ตั้งค่า Server:

```powershell
Copy-Item server/.env.example server/.env
```

5. เปิด `server/.env` ใส่ `DB_USER`, `DB_PASSWORD`, `DB_CONNECT_STRING` ของบัญชี Oracle ที่ได้รับอนุญาต เช่น `ชื่อเครื่อง:1521/ชื่อservice` จากนั้นรัน Server/Client

ถ้าเพื่อนใช้ฐานข้อมูลเดียวกันและตาราง `BUS_` มีอยู่แล้ว **ไม่ต้องรัน CREATE TABLE ซ้ำ** ข้อมูลที่แก้ผ่านเว็บจะเป็นข้อมูลชุดเดียวกัน สำหรับฐานข้อมูลใหม่ ให้อ่าน `database-review/schema-review.md` และตรวจ SQL ก่อนสร้างตาราง

ข้อมูลเชื่อมต่อ Oracle อยู่ฝั่ง Server เท่านั้น ไม่ใส่ใน React หรือไฟล์ที่เผยแพร่ไปเบราว์เซอร์

## บัญชีใช้งานและข้อมูลเริ่มต้น

เลขรหัสเรียงสำหรับข้อมูลใหม่เตรียมไว้ใน `database-review/003-readable-ids-REVIEW.sql` เพิ่ม Oracle Sequence เท่านั้น ไม่เปลี่ยนตาราง PK/FK หรือรหัสเดิม ต้องตรวจและอนุมัติก่อนรัน `node --env-file=server/.env server/scripts/migrate-sequences-reviewed.js --apply-reviewed` จากโฟลเดอร์โปรเจกต์ แล้วรีสตาร์ต Server ก่อนติดตั้งส่วนนี้ระบบยังใช้รหัสสุ่มแบบเดิม เมื่อเปิดใช้แล้วรหัสจะเป็น E006 / U002 / BK001 เป็นต้นตามเลขสูงสุดที่มี เลขไม่ซ้ำและไม่ใช้ซ้ำหลังลบ แต่อาจข้ามจากการยกเลิกหรือ rollback รหัส QR และ session ยังคงสุ่มเพื่อไม่ให้คาดเดาได้

ตอนฐานข้อมูลยังไม่มีพนักงาน เว็บจะแสดงหน้าตั้งค่าบัญชี Admin ครั้งแรก ให้กำหนด Username และ Password ของเว็บเอง รหัสผ่านเว็บแยกจากรหัส Oracle

- ผู้ใช้ทั่วไปสมัครสมาชิกจากหน้าเข้าสู่ระบบ
- Admin เพิ่มพนักงานและกำหนดรหัสผ่านในหน้าจัดการพนักงาน
- ใช้ช่อง Username / Password ชุดเดียว ระบบตรวจบัญชีแล้วเปิดหน้า Admin, Driver หรือ User ให้อัตโนมัติ
- Username ต้องไม่ซ้ำกันระหว่าง `BUS_USERS` และ `BUS_EMPLOYEES`
- Password แสดงเป็น `********` และเก็บเป็น scrypt hash ในฐานข้อมูล

ถ้าต้องการนำข้อมูลเริ่มต้นตาม Figma เข้าในฐานข้อมูลว่าง ให้ตกลงนำเข้าข้อมูลก่อน แล้วรันคำสั่งนี้ **ก่อนตั้งค่าบัญชี Admin ผ่านเว็บ**:

```powershell
npm.cmd --prefix server run seed
```

สคริปต์ตรวจว่าตารางหลักว่างก่อนทำงานและจะไม่เขียนทับข้อมูลเดิม สร้าง 3 เส้นทาง, รถ 5 คัน, พนักงาน 5 คนพร้อม Admin, ผู้ใช้ 1 คน และรอบรถล่วงหน้า 14 วัน สร้างรหัสผ่านใหม่และบันทึกใน `server/private/starter-accounts.json` บนเครื่องที่รันเท่านั้น Username หลักคือ `admin`, `driver`, `user`

รอบรถของคนขับถูกจัดไม่ให้เวลาทับซ้อนกัน เวลารวมเส้นทางคำนวณจากจุดจอดจริง ไม่มีการนำตัวเลขรายงานหรือประวัติการจองจำลองจาก Figma มาใส่เป็นรายการจริง

## SQL ส่วนเพิ่มที่ต้องตรวจ

ไฟล์รวมสำหรับฐานข้อมูลใหม่: `database-review/BUS-SHUTTLE-ALL-IN-ONE.sql` รวมตรวจชื่อซ้ำ สร้างตารางหลัก และส่วนเพิ่ม Driver/ข้อมูลรถ เปิดด้วย SQL Developer แล้ว Run Script (F5) หลังตรวจ SQL โดยส่วนสร้างจะปฏิเสธทันทีหากพบชื่อเดิม ฐานข้อมูลปัจจุบันมีโครงสร้างครบแล้ว ไม่ต้องรันไฟล์รวมซ้ำ

ตาราง 13 ตารางเดิมรองรับงานหลัก แต่ Figma มีรายละเอียดเพิ่มเติม:

- ยี่ห้อ/ปี/สถานะรถ → เพิ่มคอลัมน์ใน `BUS_VEHICLES`
- เริ่มงาน/ผ่านจุดจอด/จบงาน → `BUS_TRIP_EVENTS`
- PK ใหม่: `event_id`
- FK: `trip_id → BUS_TRIP_ROUNDS.trip_id`
- FK: `route_stop_id → BUS_ROUTE_STOPS.route_stop_id` (เฉพาะเหตุการณ์ผ่านจุดจอด)

ไฟล์ส่วนเพิ่มคือ `database-review/002-web-features-REVIEW.sql` **เจ้าของงานอนุมัติและรันสำเร็จแล้ววันที่ 28 กันยายน 2569** ฐานข้อมูลปัจจุบันเปิดใช้ Driver ได้แล้ว ไม่ต้องรันซ้ำ ไม่มีคำสั่งลบตารางเดิม

เฉพาะฐานข้อมูลใหม่ที่ยังไม่มีส่วนเพิ่ม ให้ตรวจและอนุมัติ SQL ก่อนใช้:

```powershell
npm.cmd --prefix server run migrate:reviewed -- --apply-reviewed
```

จากนั้นหยุดและเปิด Server ใหม่ ก่อนติดตั้งส่วนเพิ่ม ปุ่มเริ่มงาน/เช็กอินจุดจอดจะยังไม่เปิดใช้ และฟอร์มรถจะแสดงเฉพาะคอลัมน์เดิม

## วิธีใช้งานหลัก

- **จัดการการจอง:** Admin ค้นหาตามรหัสผู้ใช้/ชื่อ/รหัสจอง/เส้นทาง กรองวันและสถานะ ดูตั๋วแต่ละใบ ยกเลิกพร้อมเหตุผลที่ User เห็นในประวัติการยกเลิก และลบถาวรได้เมื่อการจองยกเลิกแล้ว/เดินทางจบ/ไม่มาขึ้นรถ โดยต้องไม่มีตั๋วที่ใช้งานหรือรอบที่กำลังเดินทาง
- **ลบ User ที่เคยจอง:** หน้าจัดการผู้ใช้งาน → จัดการการจองของคนนั้น → ยกเลิกรายการที่ยังใช้งานพร้อมเหตุผล → ลบถาวรรายการที่ไม่ต้องการทั้งหมด → กลับไปลบ User การลบถาวรลบทั้ง BUS_BOOKING_DETAILS และ BUS_BOOKINGS ใน transaction เดียว ประวัติ เหตุผล และตัวเลขรายงานจะเปลี่ยน และย้อนจากเว็บไม่ได้
- `004-booking-cancellation-REVIEW.sql` อนุมัติและติดตั้งแล้ววันที่ 28 กันยายน 2569 เพิ่มเหตุผล เวลา และชื่อผู้ยกเลิกในตารางเดิม ไฟล์ ALL-IN-ONE รวมส่วนนี้สำหรับติดตั้งฐานข้อมูลใหม่แล้ว ไม่ต้องรันซ้ำในฐานข้อมูลปัจจุบัน

- รอบประจำ 18:00 น. ทั้ง 3 เส้นทางสร้างล่วงหน้า 90 วันใน Oracle และเติมทุกชั่วโมงขณะ Server ทำงาน รวมถึงตอนเปิด Server ค่าเส้นทาง/รถ/คนขับอยู่ใน `server/config/daily-rounds.json` หากมีรถหรือคนขับชนรอบเดิมจะข้ามรายการนั้นและแสดงจำนวนใน Terminal
- รอบประจำที่แก้ไขหรือยกเลิกจะไม่ถูกสร้างกลับ การลบรอบประจำเก็บสถานะยกเลิกไว้
- หน้าตารางเดินรถแยกตามเส้นทาง หน้าข้อมูลรถแยกรถตู้/รถบัส และหน้าสิทธิ์เป็นตารางสวิตช์รายตำแหน่ง เลือกโหมดดูข้อมูลหรือแก้ไขข้อมูล แล้วบันทึกทุกตำแหน่งพร้อมกัน

- **Admin:** จัดการเส้นทางและจุดจอดก่อน/หลังจุดอ้างอิง, รอบรถตามวันที่, พนักงาน, รถ, สิทธิ์ตำแหน่ง และรายงาน
- **User:** เลือกวัน/เส้นทาง/จุดขึ้นลง/รอบ/ที่นั่ง → เพิ่มรายการรอยืนยัน → เลือกยืนยันบางรายการหรือทั้งหมด → ดูตั๋วแต่ละที่นั่ง
- **Driver:** เลือกวันดูงานของตนเอง → เริ่มงาน → เช็กอินจุดจอดตามลำดับ → จบงาน และรับรหัส QR จากเครื่องอ่านหรือพิมพ์รหัสบนตั๋วเพื่อเช็กอินผู้โดยสาร
- คลิกแก้ไขจะเปิดฟอร์มทันที กล่องยืนยันจะแสดงหลังคลิกบันทึก ส่วนปุ่มลบและยกเลิกการจองถามก่อนดำเนินการ
- การจองและตั๋วที่ยกเลิกยังอยู่ในฐานข้อมูล และแสดงในหน้าประวัติการยกเลิก
- ลบจุดจอดแล้วระบบลบทั้งรายการของเส้นทางและชื่อจุดในฐานข้อมูลเมื่อไม่มีเส้นทางอื่นใช้อยู่ จุดที่ใช้ร่วมกันจะยังเก็บไว้
- `E-ADMIN` เป็นบัญชีหลัก ลบไม่ได้และ Admin อื่นแก้ไขบัญชีนี้ไม่ได้ เฉพาะ `E-ADMIN` ลบ Admin อื่นได้ และทุกบัญชีลบตัวเองไม่ได้
- **จัดการผู้ใช้งาน:** Admin ค้นหา เพิ่ม และแก้ไขชื่อ Username เบอร์โทร ประเภท และรหัสผ่านของ User ได้ รหัสผ่านแสดงเป็น `********` การแก้ไขถามยืนยันตอนบันทึก และการลบถามยืนยันก่อนลบจริง บัญชีที่มีประวัติการจอง (รวมที่ยกเลิกแล้ว) ลบไม่ได้ตาม FK `BUS_FK_BOOKING_USER` โดยแสดงจำนวนและเหตุผลในหน้าเว็บ

## กติกาที่ Server ตรวจจริง

- จองครั้งละ 1–4 ที่นั่ง ก่อนเวลาออกรถอย่างน้อย 20 นาที
- ที่นั่งถูกกันทั้งรอบรถ ตาม unique index ที่มีอยู่
- ยืนยันตะกร้าหลายรายการใน transaction เดียว หากรายการหนึ่งไม่ผ่าน จะไม่บันทึกรายการอื่นในชุดนั้น
- จุดขึ้นต้องมาก่อนจุดลง และเป็นจุดในเส้นทางของรอบนั้น
- ตรวจรถ/คนขับไม่ให้ช่วงเวลาเดินรถทับกัน รวมกรณีข้ามวัน
- รหัสตั๋วอ้างด้วย `booking_id / ticket_no` และมี QR เฉพาะตั๋วแต่ละที่นั่ง
- ผู้ใช้เห็น/ยกเลิกได้เฉพาะใบจองตนเอง คนขับดำเนินงานได้เฉพาะงานตนเอง
- เก็บเวลาเป็นเวลาท้องถิ่น `Asia/Bangkok`

ข้อมูลที่มีประวัติใช้อ้างอิงจะลบทิ้งไม่ได้ เมื่อมีการจองแล้ว จะไม่เปลี่ยนจุดจอดของเส้นทางหรือเปลี่ยนเวลาของรอบนั้นโดยเงียบ ๆ ให้สร้างเส้นทาง/รอบใหม่ การลบรอบที่มีผู้จองจะเปลี่ยนเป็นยกเลิกและคงประวัติไว้แทน

## ทดสอบและ Build

```powershell
npm.cmd test
npm.cmd --prefix server run test:db
npm.cmd run build
```

`test:db` ใช้ข้อมูลทดสอบชั่วคราวที่มีรหัสเฉพาะรอบทดสอบ แล้วล้างเฉพาะข้อมูลที่สร้างขึ้น การทดสอบงานคนขับเต็มวงจรจะทำเมื่อมี SQL ส่วนเพิ่มแล้ว

หลัง Build สามารถใช้ Server เสิร์ฟเว็บสำเร็จรูปที่ `http://localhost:3001` ได้ด้วย `npm.cmd --prefix server start` โดยไม่เปิด Client dev server

ดู Admin → รายงาน → ปี 2569 เพื่อดูสถิติรายเดือน/จุดจอด/เส้นทาง/คนขับ หรือ Admin → จัดการการจอง เพื่อค้นหาและกรองรายการ หน้ารายการแบ่งครั้งละ 50 รายการ

สคริปต์นำเข้าเฉพาะข้อมูล ไม่สร้างตาราง/Sequence และไม่แตะบัญชีเดิม ถ้าจะใช้กับฐานข้อมูลใหม่ที่ติดตั้ง SQL 002/004 และข้อมูลเส้นทางเดิมแล้ว:

```powershell
cd server
node --env-file=.env scripts/seed-report-demo.js
# คำสั่งข้างบนแสดงตัวอย่างก่อนนำเข้า ตั้ง DEMO_PASSWORD เป็นรหัสผ่านที่ต้องการก่อนใช้ --apply
node --env-file=.env scripts/seed-report-demo.js --apply
node --env-file=.env scripts/verify-report-demo.js
```

ฐานข้อมูลปัจจุบันมีข้อมูลแล้ว **ไม่ต้องรันนำเข้าซ้ำ** สคริปต์จะตรวจ username ของชุดนี้และหยุดเพิ่มข้อมูลซ้ำ ไม่มีการล้างข้อมูลเดิม การตรวจสถิติแบบ exact count ของ verify script อ้างจำนวน ณ เวลานำเข้า หากใช้งาน/ลบ/แก้ข้อมูลชุดนี้ภายหลัง ตัวเลขอาจเปลี่ยน

## การสำรองเวอร์ชันโค้ด

มี ZIP เก็บเวอร์ชันตามวันที่สำหรับส่งต่อและย้อนโค้ด พร้อม `VERSION-MANIFEST.json` ระบุ SHA-256 ของไฟล์ในเวอร์ชันนั้น การย้อนโค้ดไม่ใช่การย้อนข้อมูล Oracle ให้สำรองฐานข้อมูลแยกเมื่อจะเปลี่ยนโครงสร้างหรือข้อมูลสำคัญ ไม่ใส่ `.env` หรือ `server/private` ใน Git/ZIP
